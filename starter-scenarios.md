# Шесть сценариев стартовых проектов

> **Для желающих.** Справочник на тот момент, когда кусочек продукта готов и хочется второй
> проект. Основа: глава «Шаблоны стартовых проектов» из теории курса, переложенная под то,
> как мы работаем: без сервера, на GitHub Pages, через дорогу «обсудить → допросить →
> записать → разбить → делать по одной».

## Как выбирать

Агенту удобны задачи, где результат **видно и можно потрогать**: открыл страницу, нажал,
работает или нет. Неудобны задачи, где правильность не проверить глазами: деньги, личные
данные, доступы, «чтобы работало на сервере у клиента». Начинай с первых, вторые бери, когда
освоишься.

Ещё одно правило: **чем больше в проекте внешнего мира** (чужие сервисы, базы, вход по
паролю), тем больше в нём мест, где сломается не у тебя. Первые три сценария обходятся без
этого совсем.

## Шесть сценариев

| # | Сценарий | Что внутри | GitHub Pages | Для кого |
|---|---|---|---|---|
| 1 | **Личная страница** | имя, о себе, ссылки, адаптив под телефон | ✅ целиком | ты это уже сделал: Persona |
| 2 | **Список дел с памятью** | добавить, отметить, удалить, фильтры; данные живут в браузере (localStorage) | ✅ целиком | первый проект, где страница что-то помнит |
| 3 | **Панель с живыми данными** | погода, курсы, расписание из открытого источника без ключа; загрузка, ошибки | ✅ если источник без ключа | первый выход страницы в интернет |
| 4 | **Заметки с сервером и базой** | свой сервер, база данных, вход | ❌ нужен хостинг | после курса, когда понадобится настоящий бэкенд |
| 5 | **Помощник в командной строке** | программа, которая раскладывает файлы, переименовывает, собирает отчёт | не про сайт | тем, у кого есть рутина с файлами |
| 6 | **Инструмент для команды** | общий список, которым пользуются несколько человек | ❌ нужен сервер | после курса; для старта годится вариант 2, который каждый ведёт у себя |

## Как начать любой из них

Не надо писать огромный промпт с требованиями. Иди по той же дороге, что с кусочком продукта:

1. **Обсудить.** Новая папка в `work/StartUp/`, затем: «Проведи со мной брейншторм, используй
   skill superpowers:brainstorming. Хочу [сценарий своими словами]. Страница живёт на GitHub
   Pages, без сервера».
2. **Настроить проект.** Репозиторий на GitHub и
   [`pocock-setup.md`](prompts/pocock-setup.md), часть 2.
3. **Допросить, записать, разбить.** Промпты
   [`product-piece-grilling.md`](prompts/product-piece-grilling.md) →
   [`product-piece-spec.md`](prompts/product-piece-spec.md) →
   [`product-piece-tickets.md`](prompts/product-piece-tickets.md), заменив «кусочек продукта»
   на свой проект.
4. **Делать по одной.** [`first-ticket.md`](prompts/first-ticket.md), одна задача на одну
   новую сессию.

## Что проверять в каждом

- Открыть в браузере и пройти главный сценарий руками.
- Сузить окно до ширины телефона: всё читается?
- Обновить страницу: то, что должно сохраниться, сохранилось?
- Пустой ввод, очень длинный текст, нет интернета: страница не ломается и говорит по-человечески?

# Скиллы Мэтта Покока: ставим и настраиваем проект

**Когда:** начало практики занятия 5.
**Что делает:** ставит плагин `mattpocock-skills` с готовыми скиллами для работы по шагам и
настраивает твой проект `landing`: задачи будут жить на GitHub, а у проекта появится карта,
файл `CLAUDE.md`.
**Как использовать:** часть 1 руками, мышкой. Часть 2 промптом, из папки проекта.

Проект: [github.com/mattpocock/skills](https://github.com/mattpocock/skills). Мэтт Покок
известный преподаватель разработки, это скиллы, с которыми он работает каждый день. Из
двух десятков нам нужны четыре: **grilling** (допрос), **to-spec** (записать договорённость),
**to-tickets** (разбить на задачи), **implement** (сделать задачу).

## Часть 1. Ставим плагин (руками)

Так же, как Superpowers на занятии 4. Агент сам себе плагины не ставит, и это правильно.

1. В окне Claude Code набери `/plugin` и выбери **Manage plugins**.
2. Вкладка **Marketplace**, в поиске **mattpocock-skills**, нажми **Install**.
3. Спросят, куда ставить, выбирай **для себя** (user).
4. **Закрой VS Code целиком и открой заново** (macOS Cmd+Q, Windows закрыть все окна).

**Проверка:** набери в окне ввода `/mattpocock`. Выпадает список скиллов (`grilling`,
`to-spec`, `to-tickets`, `implement` и другие)? Плагин стоит.

> Каталог висит на «Loading plugins»? Перезапусти VS Code полностью. Не помогло,
> переподключи VPN **на ту же страну**, что обычно.

## Часть 2. Настраиваем проект landing

Открой в VS Code папку **`work/StartUp/landing`** (File → Open Folder). Не `work`, а сам
проект: настройка пишется в ту папку, где ты сейчас.

Отправь:

```text
/mattpocock-skills:setup-matt-pocock-skills

Это мой проект: лендинг идеи и кусочек продукта, который мы будем строить
по задачам. Репозиторий уже есть на GitHub.

На вопросы отвечаю так:
- задачи храним в GitHub Issues этого репозитория;
- метки оставляем по умолчанию;
- если CLAUDE.md ещё нет, создай CLAUDE.md.

Когда закончишь с настройкой, допиши в начало CLAUDE.md короткую карту проекта
простыми словами, для человека, который видит его впервые:
- что это за проект и в чём идея (возьми из документов дизайна в docs/superpowers/specs);
- что где лежит в папке;
- как сайт публикуется (GitHub Pages, после push);
- как мы работаем: одна задача на GitHub = одна новая сессия.

Пиши по-русски. В конце закоммить и запушь.
```

## Что будет происходить

1. Агент осмотрит папку и покажет, что нашёл.
2. Спросит про трекер задач: подтверди **GitHub**.
3. Спросит про метки: **да, по умолчанию**.
4. Покажет черновик файлов. Всё нормально, скажи «да».
5. Создаст `CLAUDE.md` и папку `docs/agents` с настройками, заведёт метки на GitHub.
6. Допишет карту, закоммитит и запушит.

**Проверка:** открой `CLAUDE.md` глазами. Понятно, что за проект и что где лежит? Это и есть
карта: её прочитает каждая новая сессия.

## Если что-то не так

- **Агент спрашивает про GitLab, Jira, локальные файлы** → «GitHub Issues этого репо».
- **Ругается, что нет репозитория на GitHub** → «Создай публичный репозиторий landing на
  моём GitHub и запушь туда эту папку». Значит, лендинг на занятии 4 не доехал до Pages.
- **Команда `/mattpocock-skills:…` не находится** → в окне ввода набери `/` и начало слова
  `setup`, выбери скилл из списка. Нет его в списке, плагин не встал: вернись к части 1.
